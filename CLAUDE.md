# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

cc-core (`github.com/wjsoj/cc-core`) is the **shared library** behind two sibling reverse-proxy forks — **CPA-Claude** (`/home/wjs/Documents/project/Go/CPA-Claude`, the leaner one) and **hypitoken** (`/home/wjs/Documents/project/Go/hypitoken`, which adds SaaS/shop product layers). Both Go modules are confusingly *both* named `CPA-Claude`; both import this module. It has **no binary and no `main`** of its own — it is consumed, not run.

Everything that is identity-, credential-, billing-, or fingerprint-bearing lives here so the two forks can't drift apart on the parts that must stay byte-identical to a real client. A change here reaches production only when a fork **bumps the `cc-core` dependency and redeploys** — so the release unit is a git tag (`v0.8.x`), and "fix it in cc-core, then bump both forks" is the standard loop.

Derivative of [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) (MIT); the Anthropic OAuth refresh, Codex JWT parsing, and uTLS Chrome transport originated upstream.

## Build & test

No Makefile, no bun, no in-repo CI — this is a pure Go library (go 1.25).

```bash
go build ./...                              # compile everything
go test ./...                               # all tests
go test ./auth/ -run TestSessionsHeld -v    # a single test
go test ./sidecar/ -timeout 60s             # sidecar suite runs ~23s of real timing
go vet ./...
```

### Releasing (the important workflow)

```bash
git tag v0.8.NN && git push origin main v0.8.NN
```

Then in each consuming fork: `go get github.com/wjsoj/cc-core@v0.8.NN && go mod tidy`, rebuild, redeploy. Tags are lightweight, on a commit whose subject already describes the change. **Both forks share this repo as their working tree's sibling** — if another agent/session is mid-change here, only commit and push your own files (check `git status` before tagging), and use the next free tag number if yours is taken.

## Architecture — the subsystems that span files

### `auth` — the credential scheduler + health state machine (most load-bearing, most edited)

`auth.Pool` (`pool.go`) schedules OAuth/API-key credentials. `Acquire(ctx, provider, clientToken, group, model, sessionID, exclude...)` → `AcquireWithOptions(..., AcquireOptions{AllowAPIKeyFallback, APIKeyOnly, ExcludeIDs})`: sticky reuse of a healthy assignment → among usable OAuth in the tier with spare `max_concurrent`, the one with the **least weighted token usage** (`SetUsageLoadFunc`; *not* fewest sessions) → API-key fallback scanned in `Order`. Tiers are `{clientGroup}` then the shared `{"new", ""}`, and a named-group client sticky-bound to public is force-upgraded back to its own group. `claude-fable-5` and its dated/1M variants are API-key-only (`AnthropicModelRequiresAPIKey`, checked on the *first* line of `oauthUsableLocked`, so it also breaks an existing sticky binding): Anthropic rejects those accounts with `credits_required` even when their included allowance is untouched — and with `AllowAPIKeyFallback: false` they return `nil` rather than falling back to OAuth. The reserved `"new"` group is **idle 10 randomly-chosen hours per local day** (`schedule.go`, seeded by date+group so every instance agrees without shared state). `Release`/`Unstick`/`ReportUpstreamError` take the same `sessionID`. A "session" is one `(provider, clientToken, sessionID)` slot within `ActiveWindow`; `SessionsHeld` reports how many slots a token holds (input to the forks' per-token WS fair-share cap).

**Health lives on `auth.Auth` (`types.go`) and every rule here has bitten production — treat this as a spec, not a heuristic:**
- `MarkSuccess/Failure/HardFailure/RateLimited/AuthRejection/UsageLimitReached/ModelRateLimited/ClientCancel`. `ConsecutiveFailures ≥ hardFailureThreshold` (**5**) auto-hard-fails an OAuth credential; `Consecutive429s ≥ 15` → suspected stealth-ban hard-fail; `Consecutive401s ≥ auth401HardFailureThreshold` (**8**, `MarkAuthRejection`) → presumed revoked entitlement. A *single* 401 is almost always the token-rotation race (a fresh token invalidates the old one under in-flight requests), which is why the threshold is 8 with no success in between.
- **API keys are never auto-hard-failed sticky** — `Kind == KindAPIKey` short-circuits `IsHealthy` to `!quarantined` (not to `true`). They are governed by a **bounded circuit breaker** instead: `QuarantineUntil` / `QuarantineStrikes`, opened at `apiKeyQuarantineThreshold` (**3**) failures — or immediately (threshold **1**) on `MarkHardFailure`, an explicit credential rejection — with exponential backoff `10s → 30s → 2m → 5m → 15m` plus ±20% jitter. Expiry clears the deadline but **not** the strikes; only `MarkSuccess` closes the breaker. Rationale: a relay channel that is the only route for a model must be able to come back on its own.
- **`IsHealthy` degraded self-recovery** (`degradedProbeAfter`, **5 min**): a credential with `ConsecutiveFailures ≥ 2` is quarantined, but re-probed once the interval elapses — otherwise unhealthy → never Acquired → never a success to reset the counter → *permanently* dark. `HealthSnapshot` (admin panel) duplicates this logic without re-locking; **keep the two in sync.** Note that routing does *not* consult `IsHealthy`: `oauthUsableLocked` deliberately lets a degraded-but-not-hard-failed credential keep taking traffic, because skipping it is only safe when someone else is available and the scheduler can't know that — the 2026-07-14 outage was exactly a whole pool degrading at once with nobody left to return. The degraded window is an admin-panel judgement; the hard-fail threshold is the routing one.
- `MarkClientCancel` records a timestamp only — client disconnects must NOT touch failure counters or cooldowns. `MarkUsageLimitReached` and `MarkModelRateLimited` deliberately leave `Consecutive429s` alone, or a healthy account that merely exhausted its 5h window would march toward the stealth-ban hard-fail. `MarkModelRateLimited` is per model family (`ModelScopeAnthropicFable`) and never takes the account out of rotation for other models — but `ClearQuota` wipes the whole `ModelRateLimits` map.
- `ReportUpstreamError` maps 429 → rate-limit + **escalating** cooldown (`30s → 1m → 2m → 5m → 10m`, capped; an upstream `Retry-After` wins), 403 → 1m cooldown, 401 → 1m cooldown with the supplied `resetAt` **discarded**, 529/≥500 → `MarkFailure` with no cooldown. The 401/403/429 paths go through `MarkQuotaExceeded` and so never touch `ConsecutiveFailures`.

**Transient-vs-credential classification** (`retry.go`, `IsTransientNetErr` + `transientErrFragments`): wire-level flaps (`connection reset`, `broken pipe`, `unexpected EOF`, h2 `GOAWAY`/`PROTOCOL_ERROR`/`REFUSED_STREAM`, `http2: client conn not usable`/`no cached connection`/`client connection lost`) are retried on the **same** credential by `retryRoundTripper` and must never `MarkFailure`. Missing a string here is how a CF-edge h2-connection death once cascaded into a whole Codex pool going dark (a dead pooled conn fails every in-flight stream at once → a burst of `MarkFailure` → threshold crossed). Add regression cases to `retry_test.go` with the *verbatim* error string.

Also in `auth`: Anthropic login (`login.go` PKCE, `login_session.go` session-cookie flow, `login_probes.go` post-login probe burst, `oauth.go` credential-file `parseFile`), Codex OAuth (`codex_login.go`, `codex_jwt.go` plan/account claims, `codex_refresh.go`, `codex_models.go` per-plan `/v1/models`, `codex_usage.go` wham/usage windows, `codex_subscription.go` plan/term/renewal/delinquency — see `docs/codex-subscription.md`, `codex_reset.go` rate-limit reset credits), `hostprofile.go` (per-account synthetic Linux host), `utls.go` (Chrome-fingerprint HTTP client, cached per `(proxyURL, useUTLS)`; an invalid proxy yields a permanently-failing round-tripper — **never** a silent direct dial).

**The three ChatGPT portal probes are complements, not alternatives, and each carries its own captured header set.** `FetchCodexUsage` (wham/usage) reports how much quota is left *now*; `FetchCodexSubscription` (subscriptions + accounts/check) reports what was bought, when the term started, and whether it renews; `FetchCodexResetCredits`/`ResetCodexCredit` (`codex_reset.go`) query and spend rate-limit reset credits. Only the second can predict a credential dying for a **billing** reason — a delinquent account serves traffic normally until its grace period ends. **No probe may touch credential health on failure**: a flaky portal response says nothing about whether `/responses` works. wham/usage mirrors the *CLI's* captured headers because the CLI calls it; reset-credits mirrors the *Codex Desktop* headers; the billing endpoints are web-portal-only and are presented as a browser XHR — `browserUA` (matching the uTLS Chrome fingerprint) plus `Sec-Ch-Ua*`/`Sec-Fetch-*`/`Referer`, and **no** `Origin`, which browsers omit on a same-origin GET. Leaving User-Agent unset is not neutral: Go substitutes `Go-http-client/…`, the loudest third-party tell there is. Don't unify the sets without a capture.

`DefaultClaudeOAuthModelMap` is behavioural too: it is injected only when the key is **absent** from the credential file — writing an explicit empty `{}` is the way to clear it. It folds **every retired Opus generation onto `claude-opus-5` and every retired Sonnet generation onto `claude-sonnet-5`** (Haiku and `claude-fable-5` deliberately excluded — different price tier / API-key-only premium). Dated and `[1m]`-labelled variants need no entries: `ResolveUpstreamModel` retries on the `[1m]`-stripped base and then on progressively shorter `-`-trimmed prefixes, mirroring `pricing.Lookup`, so `claude-opus-4-8-20260315[1m]` resolves through `claude-opus-4-8`. Opus folds are billing-neutral (identical price cards); **Sonnet folds are not** — `sonnet-4-6` is 3.00/15.00 against `sonnet-5`'s introductory 2.00/10.00 until 2026-08-31 — so consumers bill on the resolved upstream name while displaying the client-facing one.

### `mimicry` — the Claude fingerprint (header + body)

`ApplyClaudeCodeHeaders` + `ApplyClaudeCodeBodyMimicry` make a request look like a real Claude Code **2.1.224** client. Version constants (`CLICurrentVersion`, `ClaudeCLIUserAgent`, the context-mode beta vectors `ClaudeAnthropicBetaFull` / `ClaudeAnthropicBeta1M` / `ClaudeAnthropicBetaCountTokens`, telemetry-only `ClaudeReportedBetas`) are in `fingerprint.go` — **they all move together** on a version bump or the User-Agent disagrees with the body's `cc_version=` billing block. `count_tokens` is its own request class (short beta list, no `X-Stainless-Timeout`). `ClaudeStainlessOS = "Linux"` intentionally differs from the macOS capture — do not "fix" it to match `crack/`. `dateline.go` scrubs the 3-bit steganographic date sentence. `SimIdentity{AccountKey, AccountUUID, ClientToken}` is the identity anchor: `DeviceIDFor` (sha256, identical for all traffic on one OAuth account), `SessionIDFor` (per-conversation, feeds both the body `metadata.user_id.session_id` and the `X-Claude-Code-Session-Id` header). Body mimicry is **skipped for Haiku** and for systems already starting with the CC prompt. Codex has its own constants (`codex.go`, `CodexCLIVersion` = **0.147.0**). Two Codex header rules are load-bearing and were verified against the codex-rs source at that tag rather than a capture: the HTTP path sends **no** `OpenAI-Beta` (`responses=experimental` appears nowhere in 0.147.0 — real Codex sets the header only on the WS handshake, `codexws.CodexOpenAIBetaWS`), and every ChatGPT-OAuth request carries **`x-codex-routing-hint: model=<upstream-model>[;tier=priority|flex]`** (`CodexRoutingHint`), which the backend uses to resolve some models — omitting it is how third parties get "Model not found gpt-5.6-luna-…" on an account where the official CLI works.

Genuine Claude Code traffic forwarded through Anthropic OAuth uses the prepared-request pipeline: `ClassifyClaudeCodeRequest(original)` → `NewClaudeCodeRequestPolicy` → `PrepareClaudeCodeRequest` → `ApplyClaudeCodePreparedRequest`. Preparation binds the body to the selected account key and credential kind; the final call validates that stable binding, reads the latest rotatable bearer, and installs both body and headers from the same opaque result. The rewrite maps metadata to the selected OAuth account, maps the source session by account+client token, and pins the billing version plus UA/Stainless core profile. Custom-base-url Claude Code requests do not emit first-party `cch` or `cc_prev_req`; if either unexpectedly appears, preparation fails closed rather than forwarding a value the proxy cannot safely regenerate or rebind. Request `Anthropic-Beta` is retained because main, 1M, and title carry different feature vectors; a genuine rewrite with no downstream beta vector fails closed instead of inventing the wrong one. A preparation error must not trigger credential failover — it is a local judgement, and retrying it on another credential only burns the pool. The old per-credential `claude_identity_mode` experiment is retired: credential loading ignores that legacy key and credential writes remove it. Generic (non-Claude-Code) traffic has **two** modes (`GenericRequestMode`): `GenericRequestLegacy` — the historical best-effort shaping every existing caller still gets — and `GenericRequestSynthesize`, the strict fail-closed account-bound path for generic traffic selected onto an Anthropic OAuth credential, reached only via the separate `NewGenericClaudeCodeSynthesizePolicy()` constructor so callers opt in explicitly. The lower-level `GenuineRequestPreserve` mode remains available to library callers that explicitly need byte-exact preservation.

### `sidecar` — auxiliary traffic emulation

`Manager.Notify(auth, clientToken)` fires, on first touch of an account (the dedupe anchor is `auth.AccountKey()` alone — `sidecar.go:270` — despite the older comment nearby saying `(account, clientToken)`), the bootstrap burst + heartbeats real CC emits at startup (GrowthBook, oauth/account/settings, bootstrap, quota probe, mcp-registry, event_logging `/v2/batch` every ~18s, …), each with its own captured `User-Agent`/`Anthropic-Beta`. Per-account host telemetry comes from `auth.HostProfile` so distinct accounts don't all advertise one identical machine. **API-key credentials never trigger sidecars.** The Datadog heartbeat is defined but deliberately unwired. Tests run against a live `httptest.Server` with real timing (~23s).

### The ledger + gates

- `usage` — per-auth and per-client-token consumption (`Store.Record` for auth token totals + load-balancing weight via `WeightedTotal`; `RecordClient`/`WeeklyCostUSD` for client billing). `Counts` carries token counts (+`Requests`); cost is passed alongside, not stored in `Counts`. `CacheCreate1hTokens` is a **subset** of `CacheCreate` and is deliberately excluded from `WeightedTotal` so it isn't double-counted. `usage/dedup.go` adds request-level billing idempotency (`Deduper`, keyed `requestID\x00scope`, 10m TTL, 32768 entries, **fail-open on an empty request id**) — a retried terminal event must not bill twice.
- `pricing` — `(provider, model)` → per-token USD (input 1× / cache_create 1.25× / cache_read 0.1× / output 5× weighting mirrors the load-balance signal). Catalog is append-only; **new models must be added or they bill at 0** — silently. `CacheCreate1hPer1M` is opt-in per card (0 = fold 1h writes into the normal cache-create rate). Every billed amount goes through `QuantizeUSD` (`MonetaryScale = 8` decimal places) so two servers agree to the cent. Time-limited promo cards are registered in `pricing/intro_expiry_test.go`; the test **fails the build the day a promo lapses** so an expired rate can't quietly under-bill (`claude-sonnet-5`'s introductory rate expires 2026-08-31 → list price 3.00/15.00/0.30/3.75). Add a row there with any new limited-time card.
- `requestlog` — one JSON line per terminal request to a daily file, **plus a SQLite index (`requests.db`) inside the same directory** that `Query` / `AggregateByAuth` / `AggregateHourly` serve from. The JSONL stays the source of truth; the index is derived, rebuilt from it on demand, and the three functions fall back to scanning when no index is open, so **no call site changes and a broken index only costs speed**. A host opts in with `OpenStore(dir)` (registered per-directory, looked up by `Filter.Dir`). Ingest is an incremental tail read that self-heals on truncate, retention delete, and the equal-size in-place rewrite `RewriteClientMask` performs (mtime is the only signal there). Aggregates read `agg_cube`, not rows: one pre-summed table keyed by every low-cardinality dimension at once (`day, bday, model, client, client_token, provider, auth_id, status, user_id`), which on the production archive is 10.4k rows standing in for 984k records. `cubeEligible` sends a query there unless it carries a time bound, since a day is the cube's finest grain — that is the whole rule. It replaced a per-grouping `agg_day`, which only helped *unfiltered* queries and left `?model=X` at ~2.9s; the cube answers the same query in 10ms. Three traps: `req.day` is the **source file's UTC day** while `req.bday` is the **display-zone day** (production buckets in Asia/Shanghai, where they disagree) — changing the zone **relabels `bday` in place and rebuilds the cube from the rows** (`relabelBuckets`), deliberately *not* the old `DELETE req/agg_cube/ingest` + rescan, which destroyed all history under `JSONLArchive: false` where there is no archive to rescan; `attempt_only` rows are invisible to every query, matching `matches()`; and every index is partial on `attempt_only = 0` and carries the sort columns, because an index that doesn't cover `ORDER BY ts DESC, id DESC` silently degrades to a full sort.

  The writer also inserts each batch straight into `req` (`store_write.go`), so the index is current within a batch instead of a scan interval. The two producers — writer and file scanner — are reconciled by a unique `(src_file, src_off)`: the byte offset a line was appended at, so whichever offers a line second is a no-op. `Writer.curOff` must resume from the file's existing size on open, or a restart re-uses offsets the previous run already claimed. That idempotency is what makes `Options{JSONLArchive: false}` possible — no files at all, SQLite as the only copy, `pruneBefore` enforcing retention and `RewriteClientMask` collapsing to one `UPDATE`. It is opt-in per host and stays off by default: with no archive, a failed insert is a lost record and there is nothing to rebuild from. `Export` writes the rows back out as JSONL, which is the way back.
- `ratelimit` — keyed `RPM` + `Concurrency` (pure counters; policy/limit lives in the caller).
- `clienttoken` — runtime store of client access tokens.
- `clientguard` — shared ingress UA blocklist.

## Conventions worth knowing

- **All identity derivation is content-addressed** — no random UUIDs except `X-Client-Request-Id` and the internal `event_id`. New stable identifiers derive from `accountKey` (or `accountKey + clientToken` when they should differ per downstream user), so they survive credential-file rotation.
- **OAuth credential-file fields are append-only** — `parseFile` (`auth/oauth.go`) tolerates missing fields via the `_ = raw["new_field"].(...)` pattern so old files keep loading.
- **Pricing & health thresholds are behavioural constants** — changing `hardFailureThreshold`, `degradedProbeAfter`, the pricing weights, or a `transientErrFragments` entry changes production behaviour in both forks at once. Pair every such change with a test.
- **Fingerprint constants must match `crack/`** — never hand-edit a User-Agent/beta/body-shape without a capture backing it; the diff belongs in `crack/cc<ver>/SPEC.md`.
- **Probes and local preparation errors are not credential failures** — portal probes (`codex_usage`/`codex_subscription`/`codex_reset`) and `PrepareClaudeCodeRequest` failures must never call `MarkFailure` or trigger failover.
