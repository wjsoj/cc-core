# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

cc-core (`github.com/wjsoj/cc-core`) is the **shared library** behind two sibling reverse-proxy forks — **CPA-Claude** (`/home/wjs/Documents/project/Go/CPA-Claude`, the leaner one) and **hypitoken** (`/home/wjs/Documents/project/Go/hypitoken`, which adds SaaS/shop product layers). Both Go modules are confusingly *both* named `CPA-Claude`; both import this module. It has **no binary and no `main`** of its own — it is consumed, not run.

Everything that is identity-, credential-, billing-, or fingerprint-bearing lives here so the two forks can't drift apart on the parts that must stay byte-identical to a real client. A change here reaches production only when a fork **bumps the `cc-core` dependency and redeploys** — so the release unit is a git tag (`v0.8.x`), and "fix it in cc-core, then bump both forks" is the standard loop.

Derivative of [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) (MIT); the Anthropic OAuth refresh, Codex JWT parsing, and uTLS Chrome transport originated upstream.

## Build & test

No Makefile, no bun, no in-repo CI — this is a pure Go library (go 1.25).

```bash
go build ./...                              # compile everything
go test ./...                               # all tests
go test ./auth/ -run TestSessionsHeld -v    # a single test
go test ./sidecar/ -timeout 60s             # sidecar suite runs ~23s of real timing
go vet ./...
```

### Releasing (the important workflow)

```bash
git tag v0.8.NN && git push origin main v0.8.NN
```

Then in each consuming fork: `go get github.com/wjsoj/cc-core@v0.8.NN && go mod tidy`, rebuild, redeploy. Tags are lightweight, on a commit whose subject already describes the change. **Both forks share this repo as their working tree's sibling** — if another agent/session is mid-change here, only commit and push your own files (check `git status` before tagging), and use the next free tag number if yours is taken.

## Architecture — the subsystems that span files

### `auth` — the credential scheduler + health state machine (most load-bearing, most edited)

`auth.Pool` (`pool.go`) schedules OAuth/API-key credentials. `Acquire(ctx, provider, clientToken, group, model, sessionID, exclude...)` → `AcquireWithOptions(..., AcquireOptions{AllowAPIKeyFallback, APIKeyOnly, ExcludeIDs})`: sticky reuse of a healthy assignment → among usable OAuth in the tier with spare `max_concurrent`, the one with the **least weighted token usage** (`SetUsageLoadFunc`; *not* fewest sessions) → API-key fallback, **scanned in two rounds** (see below). Tiers are `{clientGroup}` then the shared `{"new", ""}`, and a named-group client sticky-bound to public is force-upgraded back to its own group. `claude-fable-5` **used to be** API-key-only (`AnthropicModelRequiresAPIKey` on the first line of `oauthUsableLocked`) because Anthropic rejected subscription accounts with `credits_required`; **that gate was removed 2026-08-25** when fable became permanently plan-included, and it now routes like any other model (keeps sticky bindings, served from OAuth even with `AllowAPIKeyFallback: false`). The helper stays exported as the rollback anchor. **Do not confuse that with fable's per-model quota, which remains**: `ModelScopeAnthropicFable` + `MarkModelRateLimited` make a spent fable window skip the credential *for fable only* — `IsQuotaExceeded` stays false, the account keeps serving every other model, and the fable traffic falls through to the API-key pool. Promoting a model-scoped limit to an account-wide one is the expensive mistake here. The reserved `"new"` group is **idle 10 randomly-chosen hours per local day** (`schedule.go`, seeded by date+group so every instance agrees without shared state). `Release`/`Unstick`/`ReportUpstreamError` take the same `sessionID`. A "session" is one `(provider, clientToken, sessionID)` slot within `ActiveWindow`; `SessionsHeld` reports how many slots a token holds (input to the forks' per-token WS fair-share cap).

**The API-key scan is two rounds, and the second one is the point** (`eligibleAPIKeysLocked` / `pickReadyAPIKey` / `pickLastResortAPIKey`). Round one takes only fully-usable keys, ranked `(Order, QuarantineStrikes, unverified LastFailure, slice index)` — `Order` is the operator's explicit intent and is never traded away, but the two new tiebreakers make equal-`Order` keys actually rotate instead of the scan re-picking the same first entry on every request. When round one finds nothing across every tier, `Acquire` **no longer returns `nil`**: round two releases, out of the keys blocked *only* by a self-expiring cooldown (quota or an open breaker), the one closest to coming back — ranked `(RetryAfter, QuarantineStrikes, Order, index)`. Rationale: **backoff must lower a candidate's priority, not remove it from the candidate set** — skipping the only channel that can serve a model turns the breaker's 15m ceiling into the deployment's outage length. Hard boundaries are *not* relaxed there: `Disabled`, hard-failed, `ExcludeIDs` (already tried and failed in *this* request), group idle, and provider/tier mismatch. `AcquireWithResult` returns `AcquireResult{LastResort, Reason}` so a caller can surface the degraded pick — it is **not** an error, the alternative was a 503. `Acquire`/`AcquireWithOptions` delegate to it and keep their exact signatures, because both forks call them positionally. `HasAPIKeyFor` runs the *same* eligibility split and counts paused keys as available, so the fail-fast pre-check and the scheduler can never disagree — it previously missed `IsQuarantined` and promised a route `Acquire` returned `nil` for. **That is a behaviour change both forks will see.**

**Health lives on `auth.Auth` (`types.go`) and every rule here has bitten production — treat this as a spec, not a heuristic:**
- `MarkSuccess/Failure/HardFailure/RateLimited/AuthRejection/UsageLimitReached/ModelRateLimited/ClientCancel`. `ConsecutiveFailures ≥ hardFailureThreshold` (**5**) auto-hard-fails an OAuth credential; `Consecutive429s ≥ 15` → suspected stealth-ban hard-fail; `Consecutive401s ≥ auth401HardFailureThreshold` (**8**, `MarkAuthRejection`) → presumed revoked entitlement. A *single* 401 is almost always the token-rotation race (a fresh token invalidates the old one under in-flight requests), which is why the threshold is 8 with no success in between.
- **API keys are never auto-hard-failed sticky** — `Kind == KindAPIKey` short-circuits `IsHealthy` to `!quarantined` (not to `true`). They are governed by a **bounded circuit breaker** instead (`QuarantineUntil` / `QuarantineStrikes`, backoff `10s → 30s → 2m → 5m → 15m` plus ±20% jitter), now driven by **three independent counters with three thresholds**, all through the single entry point `openBreakerLocked` (`tripQuarantineLocked` keeps its old signature and delegates): `ConsecutiveFailures ≥ apiKeyQuarantineThreshold` (**3**), `Consecutive429s ≥ apiKey429QuarantineThreshold` (**6**), `Consecutive401s ≥ apiKey401QuarantineThreshold` (**2**) — or immediately (threshold **1**) on `MarkHardFailure`, an explicit credential rejection. The strike ladder is shared: a channel failing three different ways is not three healthy channels. Only `ConsecutiveFailures` used to reach the breaker, and since `MarkRateLimited`/`MarkAuthRejection` deliberately never touch that counter, the two most common relay death modes could never open it — the key cycled "try → cooldown → try" forever without rotating. 6 > 3 because throttling means the relay works and is busy, the opposite of a 502; 2 ≪ OAuth's 8 because an API key **does not rotate**, so the token-rotation race that makes OAuth 401s ambiguous simply does not exist. **The 429 politeness exemption**: `MarkRateLimitedRetryAfter(reason, resetAt)` — which `ReportUpstreamError` now feeds — adds **no strike** when the upstream supplied a `Retry-After`/reset time; a relay answering "429, retry in 12s" is doing its job and must not be retired for being honest. Only *silent* 429s feed the breaker. The quota cooldown and the breaker are both deadlines on the same credential, so they **overlap, never sum**. `Consecutive429s` still advances either way, so OAuth's stealth-ban detection is unchanged. Expiry clears the deadline but **not** the strikes; only `MarkSuccess` closes the breaker. `ClearFailure` ("mark healthy") must clear the breaker too — leaving it would report healthy while paused and send the next trip to a late rung — while `ClearQuota` must **not**: quota is a wait the upstream imposed, breaker state is our own loss of confidence.
- **Seven-state `HealthState`** (`health_state.go`) is the display/alerting classification: `healthy / half_open / degraded / quota / cooling / hard_failed / disabled`, with strict precedence `disabled → hard_failed → quota → cooling → half_open → degraded → healthy`. **`half_open` is the load-bearing new state**: the pause elapsed and the channel is routable again, but nothing has succeeded on it since the failure that opened the circuit — the old boolean painted it green the instant the deadline passed. Never render it green; only `MarkSuccess` leaves it. `HealthReport.Serving` deliberately does **not** mirror `State` — `degraded` and `half_open` are both Serving, because routing keeps using them on purpose; read `Serving` for "can the pool serve", `State` for "what should the badge say". `Pool.Health(provider)` returns the `PoolHealth` aggregate (`Total`/`Serving`/`ByState`/`Worst`, `Available() == Serving > 0`) and is the forks' single source for "is this pool up". **`HealthSnapshot()`'s 4-tuple signature and behaviour are frozen** — both forks destructure it positionally — so new code uses `HealthState()`; `Snapshot()` now carries `State` plus the failure counters so JSON projections don't re-derive it (three call sites had grown three different ladders).
- **`IsHealthy` degraded self-recovery** (`degradedProbeAfter`, **5 min**): a credential with `ConsecutiveFailures ≥ 2` is quarantined, but re-probed once the interval elapses — otherwise unhealthy → never Acquired → never a success to reset the counter → *permanently* dark. `HealthSnapshot` (admin panel) duplicates this logic without re-locking; **keep the two in sync** — but add new logic to `healthStateLocked`, the only one of the three still growing. Note that routing does *not* consult `IsHealthy`: `oauthUsableLocked` deliberately lets a degraded-but-not-hard-failed credential keep taking traffic, because skipping it is only safe when someone else is available and the scheduler can't know that — the 2026-07-14 outage was exactly a whole pool degrading at once with nobody left to return. **The last-resort round is the same principle applied to API keys**: a `cooling`/`quota` pause is likewise only safe to skip when someone else is available, so it lowers priority rather than removing the candidate. Routing lets the request through; the health layer still reports the channel red, and `AcquireResult.LastResort` tells the caller which kind of pick it was. The degraded window is an admin-panel judgement; the hard-fail threshold is the routing one.
- `MarkClientCancel` records a timestamp only — client disconnects must NOT touch failure counters or cooldowns. `MarkUsageLimitReached` and `MarkModelRateLimited` deliberately leave `Consecutive429s` alone, or a healthy account that merely exhausted its 5h window would march toward the stealth-ban hard-fail. `MarkModelRateLimited` is per model family (`ModelScopeAnthropicFable`) and never takes the account out of rotation for other models — but `ClearQuota` wipes the whole `ModelRateLimits` map.
- `ReportUpstreamError` maps 429 → `MarkRateLimitedRetryAfter(..., resetAt)` + **escalating** cooldown (`30s → 1m → 2m → 5m → 10m`, capped; an upstream `Retry-After` wins **and spares the API-key breaker a strike**), 403 → 1m cooldown, 401 → 1m cooldown with the supplied `resetAt` **discarded**, 529/≥500 → `MarkFailure` with no cooldown. The 401/403/429 paths go through `MarkQuotaExceeded` and so never touch `ConsecutiveFailures`.

**Transient-vs-credential classification** (`retry.go`, `IsTransientNetErr` + `transientErrFragments`): wire-level flaps (`connection reset`, `broken pipe`, `unexpected EOF`, h2 `GOAWAY`/`PROTOCOL_ERROR`/`REFUSED_STREAM`, `http2: client conn not usable`/`no cached connection`/`client connection lost`) are retried on the **same** credential by `retryRoundTripper` and must never `MarkFailure`. Missing a string here is how a CF-edge h2-connection death once cascaded into a whole Codex pool going dark (a dead pooled conn fails every in-flight stream at once → a burst of `MarkFailure` → threshold crossed). Add regression cases to `retry_test.go` with the *verbatim* error string.

Also in `auth`: Anthropic login (`login.go` PKCE, `login_session.go` session-cookie flow, `login_probes.go` post-login probe burst, `oauth.go` credential-file `parseFile`), Codex OAuth (`codex_login.go`, `codex_jwt.go` plan/account claims, `codex_refresh.go` — both token-endpoint calls go through `applyCodexTokenEndpointHeaders`, which sends `accept: */*` and **suppresses User-Agent entirely** by assigning `req.Header["User-Agent"] = nil`; the captured client sends no UA there, and `Del`/`Set("")` both leave net/http free to substitute `Go-http-client/1.1`, the loudest tell in the login flow. `ParseCodexAccessToken` backfills `chatgpt_account_id`/plan/email when a refresh returns no `id_token` — reading them from the id_token alone used to pin `AccountID` at its creation value forever; `CodexIDTokenClaims` also exposes `chatgpt_subscription_active_*` and `organizations[]`, a free fallback for `FetchCodexSubscription` that is frozen at issue time and so supplements rather than replaces it), `codex_models.go` per-plan `/v1/models`, `codex_usage.go` wham/usage windows, `codex_subscription.go` plan/term/renewal/delinquency — see `docs/codex-subscription.md`, `codex_reset.go` rate-limit reset credits), `hostprofile.go` (per-account synthetic Linux host), `utls.go` (Chrome-fingerprint HTTP client, cached per `(proxyURL, useUTLS)`; an invalid proxy yields a permanently-failing round-tripper — **never** a silent direct dial).

### `mimicry` — the Claude fingerprint (header + body)

`ApplyClaudeCodeHeaders` + `ApplyClaudeCodeBodyMimicry` make a request look like a real Claude Code **2.1.224** client. Version constants (`CLICurrentVersion`, `ClaudeCLIUserAgent`, the context-mode beta vectors `ClaudeAnthropicBetaFull` / `ClaudeAnthropicBeta1M` / `ClaudeAnthropicBetaCountTokens`, telemetry-only `ClaudeReportedBetas`) are in `fingerprint.go` — **they all move together** on a version bump or the User-Agent disagrees with the body's `cc_version=` billing block. `count_tokens` is its own request class (short beta list, no `X-Stainless-Timeout`). `ClaudeStainlessOS = "Linux"` intentionally differs from the macOS capture — do not "fix" it to match `crack/`. `dateline.go` scrubs the 3-bit steganographic date sentence. `SimIdentity{AccountKey, AccountUUID, ClientToken}` is the identity anchor: `DeviceIDFor` (sha256, identical for all traffic on one OAuth account), `SessionIDFor` (per-conversation, feeds both the body `metadata.user_id.session_id` and the `X-Claude-Code-Session-Id` header). Body mimicry is **skipped for Haiku** and for systems already starting with the CC prompt. **Codex has two identities, and the default is now Codex Desktop.** `CodexClientProfile` (`codex_identity.go`) bundles the `originator` / `user-agent` / `version` triple that the backend validates against each other — never mix fields across profiles. `CodexDesktopClientProfile` (originator `Codex Desktop`, version **0.147.0-alpha.6.6**, build `26.803.81509`, `x-codex-beta-features: remote_compaction_v2`) is what `DefaultCodexProfile()` returns and what both forks now advertise; `CodexTUIClientProfile` keeps the CLI shape (`codex-tui`/**0.147.0**) for callers that want it. Ground truth is `crack/codexapp0.147.0/` (live 2026-08-14) vs `crack/codexv0.135.0/` (CLI). Pinning Desktop means pinning a **pre-release** version string — it drifts faster than a stable CLI tag, and it must not be "cleaned" to `0.147.0` because the backend parses the field and a version/UA mismatch is a one-header tell.

Three Codex header rules are load-bearing. The HTTP path sends **no** `OpenAI-Beta` (`responses=experimental` appears nowhere in 0.147.0 — real Codex sets the header only on the WS handshake, `codexws.CodexOpenAIBetaWS`). The session header is **`session-id`** — a hyphen, all lowercase; cc-core sent `Session_id` for two capture generations because Go's canonicalization leaves an underscore alone, so it must be written through a raw map assignment (`setCodexHeader`) and asserted by raw map key, never `Header.Get`. And **`x-codex-routing-hint: model=<upstream-model>[;tier=priority|flex]`** (`CodexRoutingHint`) is **HTTP-path only**: it used to go on the WS handshake too, but neither the 0.135.0 nor the 0.147.0 upgrade carries it (both send 18 headers, the hint is not among them), so `codexws` stopped. On HTTP it stands on the codex-rs source reading, which nothing contradicts — the backend resolves some models per-originator/per-hint, and omitting it is how third parties get "Model not found gpt-5.6-luna-…" on an account where the official CLI works.

**The session id is the prompt cache, so it must survive reconnects** (`codexws.SessionRegistry`). It is also `session-id`, `thread-id` and the `x-codex-window-id` prefix, but the expensive part is that it *is* `prompt_cache_key`: the captured turn bought 22272 of 22735 input tokens from upstream, and minting a fresh id per WebSocket connection pays list price on every reconnect. `CodexSessionUUIDFor` is deterministic given `(anchor, startedAt)`, so the registry exists only to remember when each conversation was **actually first seen**. Two stateless alternatives are wrong and were rejected: hashing the anchor into the timestamp lands a v7 in an arbitrary year (no genuine client does that), and bucketing `time.Now()` rotates every session the proxy serves at the *same instant across all accounts* — a cross-account correlation signal, i.e. the opposite of the goal. `Registry.Identity(accountKey, anchor)` hands the handshake and the frame rewriter one value. **The anchor must never be a value a downstream client picks alone** — it becomes our upstream prompt-cache namespace, so a caller who could steer it could aim at another tenant's cached prefix; compose it from the credential plus the downstream caller.

**`RemoveCodexPreviousResponseID` is byte-level on purpose** (`mimicry`). A relay must drop that key when the id belongs to a response served by a different credential. The obvious `unmarshal → delete → marshal` is what both forks had, and Go emits map keys **sorted**, so the frame came back with its top-level order rewritten — silently undoing the byte fidelity the rest of the frame work protects. Same rule as everywhere else here: byte splices, never map round-trips, when the shape is the fingerprint.

**The client's WS frame must be rebound before it goes upstream** (`mimicry/codex_frame.go`, `RewriteCodexClientFrame`). A relayed `response.create` carries the DOWNSTREAM client's own `client_metadata` — installation id, session/thread/turn/window ids — so forwarding it verbatim makes N downstream users look like N installations on one ChatGPT account, and makes the frame **disagree with the handshake headers**, which a genuine client always matches. The rewrite is a **single-pass literal token substitution** of canonical UUIDs, not a map round-trip: top-level key order is part of the captured shape, and the same turn id also lives in `input[].internal_chat_message_metadata_passthrough`, so substitution keeps all three copies consistent without walking `input`. Three rules are load-bearing — only canonical 36-char UUIDs are substituted (a one-character client "session id" would otherwise rewrite every occurrence of that character, JSON syntax and user prose included); the frame type comes from a real top-level parse, never a substring (a client discussing the protocol would get its cancel frame rewritten); and `prompt_cache_key` is rebound explicitly, since a client that sends its own would otherwise leak it upstream and land in a cache namespace that disagrees with the advertised session. `CodexFrameIdentity` is the same type `codexws.UpstreamHeaderOptions.Identity` takes — pass one value to both or the two halves derive different installation ids (headers fall back to the ChatGPT account UUID, the frame to the account key).

**The WS handshake now sends the five headers cc-core used to refuse** (`x-codex-turn-metadata`, `x-codex-window-id`, `x-codex-beta-features`, `thread-id`, `x-client-request-id`). The old objection was sound at 0.135.0, where `x-codex-turn-metadata` carried a `workspaces` map with the user's cwd, git remote and commit hash; 0.147.0 Desktop dropped that map, leaving only ids a proxy legitimately owns, and omitting five headers every real client sends became the larger tell. All ids are **UUIDv7** (`NewCodexSessionUUID` / `CodexSessionUUIDFor`), not v4 — the version nibble is visible on the wire — and `x-client-request-id == session-id == thread-id` with `x-codex-window-id == "<session>:0"`. `installation_id` is content-addressed per **account** (`CodexInstallationIDFor`); deriving it per client token would present one ChatGPT account as N machines. Header **order** is part of the shape and Go sorts headers alphabetically, so `codexws.handshakeOrderConn` rewrites the upgrade's header block into the captured order on the way out.

Genuine Claude Code traffic forwarded through Anthropic OAuth uses the prepared-request pipeline: `ClassifyClaudeCodeRequest(original)` → `NewClaudeCodeRequestPolicy` → `PrepareClaudeCodeRequest` → `ApplyClaudeCodePreparedRequest`. Preparation binds the body to the selected account key and credential kind; the final call validates that stable binding, reads the latest rotatable bearer, and installs both body and headers from the same opaque result. The rewrite maps metadata to the selected OAuth account, maps the source session by account+client token, and pins the billing version plus UA/Stainless core profile. Custom-base-url Claude Code requests do not emit first-party `cch` or `cc_prev_req`; if either unexpectedly appears, preparation fails closed rather than forwarding a value the proxy cannot safely regenerate or rebind. The inbound shape this pipeline consumes is captured in `crack/claudev2.1.226-inbound/` — a real Claude Code on a custom base URL — and it is missing things a first-party client sends, so the rewrite also **repairs**: the request `Anthropic-Beta` vector is kept (main, 1M, and title carry different feature vectors, and a genuine rewrite with no downstream vector fails closed rather than inventing the wrong one) but gets the five OAuth-only betas inserted at their captured positions (`UpgradeClaudeBetaVectorForOAuth`, `mimicry/beta.go` — additive, idempotent, never drops a declared beta, and deliberately does not inject the `context-1m`/`fallback-credit` context-mode pair); bare `{"type":"ephemeral"}` system breakpoints regain their `ttl`/`scope` (`mimicry/cachecontrol.go` — only on blocks that already carry one, only the last two, never adding or removing a breakpoint). Those two ship together: `ttl`/`scope` require betas the beta repair puts back. Body edits at this layer are byte splices, never map round-trips, because a map reorders JSON keys and key order is part of the captured shape — same reason `RewriteModelFieldPreservingBytes` exists, and it must run *before* preparation since the prepared result pins a body digest. A preparation error must not trigger credential failover — it is a local judgement, and retrying it on another credential only burns the pool. The old per-credential `claude_identity_mode` experiment is retired: credential loading ignores that legacy key and credential writes remove it. Generic (non-Claude-Code) traffic has **two** modes (`GenericRequestMode`): `GenericRequestLegacy` — the historical best-effort shaping every existing caller still gets — and `GenericRequestSynthesize`, the strict fail-closed account-bound path for generic traffic selected onto an Anthropic OAuth credential, reached only via the separate `NewGenericClaudeCodeSynthesizePolicy()` constructor so callers opt in explicitly. The lower-level `GenuineRequestPreserve` mode remains available to library callers that explicitly need byte-exact preservation.

### `sidecar` — auxiliary traffic emulation

`Manager.Notify(auth, clientToken)` fires, on first touch of an account (the dedupe anchor is `auth.AccountKey()` alone; `clientToken` only ever reaches log masking), the bootstrap burst + heartbeats real CC emits at startup (GrowthBook, oauth/account/settings, bootstrap, quota probe, mcp-registry, event_logging `/v2/batch` every ~18s, …), each with its own captured `User-Agent`/`Anthropic-Beta`. Per-account host telemetry comes from `auth.HostProfile` so distinct accounts don't all advertise one identical machine. **API-key credentials never trigger sidecars, and neither does any non-Anthropic provider** — every step targets `api.anthropic.com`/`downloads.claude.ai` with Anthropic betas, so without the provider guard a Codex OAuth credential would send the whole bootstrap burst authenticated with a ChatGPT access token. There is deliberately **no Codex sidecar**: the reasoning is in `crack/codexapp0.147.0/SPEC.md §6`, and the short version is that Codex's auxiliary traffic goes *directly* to `chatgpt.com`, never through the relay, so its absence is normal for the population cc-core sits in — while `analytics-events` would require fabricating turn ids that must match real `/responses` traffic, which is worse than silence. The Datadog heartbeat is defined but deliberately unwired. Tests run against a live `httptest.Server` with real timing (~23s).

They are not old-and-new versions of one client — mixing their constants 404s. The Desktop archive's `SPEC.md §7` lists the deltas we knowingly do **not** match yet, and its `README.md` lists what the capture failed to record (`/oauth/authorize`, the turn-opening `response.create` frame, the Sentry heartbeat payload). The three `claudev2.1.126*` dirs — plain OAuth, `-apikey`, `-login` — cover the rest. Capture dirs are named `<client>v<version>[-<path>]` after the version in the captured User-Agent. `scripts/extract_live.py` keeps fingerprint-bearing structure and `<masked>`s all identity/prose; raw dumps are never committed.

**Bumping the CC version target** (a cc-core-only change): capture a fresh dump → `extract_live.py <dump> crack/claudev<ver>/rows` → write `crack/claudev<ver>/SPEC.md` → update constants in `mimicry`/`sidecar` (User-Agent, betas, body layout, sidecar steps all together) → **re-capture the custom-base-url side too and refresh `crack/claudev2.1.226-inbound/SPEC.md`**, since a release can widen the OAuth-only delta without touching the OAuth vector → tag a release → bump the dependency in **both** forks. See `crack/claudev2.1.224/SPEC.md` for a worked diff (and `crack/claudev2.1.220/SPEC.md` for one backed by independent and 10-turn captures).

### The ledger + gates

- `usage` — per-auth and per-client-token consumption (`Store.Record` for auth token totals + load-balancing weight via `WeightedTotal`; `RecordClient`/`WeeklyCostUSD` for client billing). `Counts` carries token counts (+`Requests`); cost is passed alongside, not stored in `Counts`. `CacheCreate1hTokens` is a **subset** of `CacheCreate` and is deliberately excluded from `WeightedTotal` so it isn't double-counted. `usage/dedup.go` adds request-level billing idempotency (`Deduper`, keyed `requestID\x00scope`, 10m TTL, 32768 entries, **fail-open on an empty request id**) — a retried terminal event must not bill twice.
- `pricing` — `(provider, model)` → per-token USD (input 1× / cache_create 1.25× / cache_read 0.1× / output 5× weighting mirrors the load-balance signal). Catalog is append-only; **new models must be added or they bill at 0** — silently. `CacheCreate1hPer1M` is opt-in per card (0 = fold 1h writes into the normal cache-create rate). Every billed amount goes through `QuantizeUSD` (`MonetaryScale = 8` decimal places) so two servers agree to the cent. Time-limited promo cards are registered in `pricing/intro_expiry_test.go`; the test **fails the build the day a promo lapses** so an expired rate can't quietly under-bill (`claude-sonnet-5`'s introductory rate expires 2026-08-31 → list price 3.00/15.00/0.30/3.75). Add a row there with any new limited-time card.
- `requestlog` — one JSON line per terminal request to a daily file, **plus a SQLite index (`requests.db`) inside the same directory** that `Query` / `AggregateByAuth` / `AggregateHourly` serve from. The JSONL stays the source of truth; the index is derived, rebuilt from it on demand, and the three functions fall back to scanning when no index is open, so **no call site changes and a broken index only costs speed**. A host opts in with `OpenStore(dir)` (registered per-directory, looked up by `Filter.Dir`). Ingest is an incremental tail read that self-heals on truncate, retention delete, and the equal-size in-place rewrite `RewriteClientMask` performs (mtime is the only signal there). Aggregates read `agg_cube`, not rows: one pre-summed table keyed by every low-cardinality dimension at once (`day, bday, model, client, client_token, provider, auth_id, status, user_id`), which on the production archive is 10.4k rows standing in for 984k records. `cubeEligible` sends a query there unless it carries a time bound, since a day is the cube's finest grain — that is the whole rule. It replaced a per-grouping `agg_day`, which only helped *unfiltered* queries and left `?model=X` at ~2.9s; the cube answers the same query in 10ms. Three traps: `req.day` is the **source file's UTC day** while `req.bday` is the **display-zone day** (production buckets in Asia/Shanghai, where they disagree) — changing the zone **relabels `bday` in place and rebuilds the cube from the rows** (`relabelBuckets`), deliberately *not* the old `DELETE req/agg_cube/ingest` + rescan, which destroyed all history under `JSONLArchive: false` where there is no archive to rescan; `attempt_only` rows are invisible to every query, matching `matches()`; and every index is partial on `attempt_only = 0` and carries the sort columns, because an index that doesn't cover `ORDER BY ts DESC, id DESC` silently degrades to a full sort.

  The writer also inserts each batch straight into `req` (`store_write.go`), so the index is current within a batch instead of a scan interval. The two producers — writer and file scanner — are reconciled by a unique `(src_file, src_off)`: the byte offset a line was appended at, so whichever offers a line second is a no-op. `Writer.curOff` must resume from the file's existing size on open, or a restart re-uses offsets the previous run already claimed. That idempotency is what makes `Options{JSONLArchive: false}` possible — no files at all, SQLite as the only copy, `pruneBefore` enforcing retention and `RewriteClientMask` collapsing to one `UPDATE`. It is opt-in per host and stays off by default: with no archive, a failed insert is a lost record and there is nothing to rebuild from. `Export` writes the rows back out as JSONL, which is the way back.
- `downstream` — the **response** direction: what we are willing to send back to the client. Forwarding upstream headers verbatim hands the caller our pool's operational state — twelve `anthropic-ratelimit-unified-*` headers (the serving account's tier, 5h/7d utilisation, overage status, exact reset timestamps) plus `anthropic-organization-id`, `anthropic-workspace-id`, `request-id`, `cf-ray`. `CopyResponseHeaders`/`ScrubUpstreamHeaders` apply an **allowlist** (`Content-Type`, `Cache-Control`, `Retry-After`, `Vary`, `Content-Encoding` — nothing else), which is known-safe because the captured third-party gateway returns none of the rest and real Claude Code works against it (`crack/claudev2.1.226-inbound/SPEC.md §4`). It is one function, not two, because it must synthesize `Retry-After` from the unified reset timestamps *before* deleting them (rounded up to the minute, capped at 1h, so the client still backs off without learning our window boundary). Scrub the **upstream** map, never the client-facing one — the proxy sets headers of its own. `ScrubErrorPayload` drops `request_id` and redacts UUID/`req_` tokens from error free-text; `ScrubSSELine` does the same for `event: error` frames only, gated on one string compare so the thousands of delta frames per response are untouched.

  **`codex.rate_limits` is rewritten, not dropped, and it keeps a coarse backoff.** Scrubbing it to bare `{allowed, limit_reached}` would be a regression dressed as a fix: a client told it is throttled with no idea for how long retries immediately, turning one throttled credential into a hot loop against the pool. `scrubCodexRateLimits` therefore synthesizes `primary.reset_after_seconds` from the soonest window, **only when actually limited**, rounded up to the minute and capped at 1h — the same rule `ensureRetryAfter` applies on the Anthropic side, for the same reason.

  **Codex leaks through two channels that allowlist cannot reach** (`downstream/codex.go`). The WebSocket **101** is not an ordinary response: relaying it hands the client `cf-ray` (whose suffix is the Cloudflare datacentre — it locates our egress), `set-cookie` with the upstream `__cf_bm`, `x-models-etag` (a per-account catalogue version that correlates two requests to one account), and `x-openai-proxy-wasm`. `ScrubWSHandshakeHeaders`/`CopyWSHandshakeHeaders` allowlist it down to the four headers the protocol needs. And Codex sends its rate-limit state as an **in-band frame**, not headers: `codex.rate_limits` carries the serving account's plan, 7-day `used_percent`, exact `reset_at` and credit balance — the same disclosure as Anthropic's twelve unified headers, arriving where no header allowlist looks. `ScrubCodexEvent`/`ScrubCodexSSELine` **rewrite** that frame down to `{allowed, limit_reached}` (a throttled client still needs to know it is throttled), **drop** `codex.response.metadata` and `responsesapi.websocket_timing` whole (upstream turn-state token, internal safety-model name, OpenAI engine instance ids and queue depths), and delete `safety_identifier` — literally `user-<chatgpt_user_id>` of the serving account — plus `service_tier` and `prompt_cache_retention` from the `response` object echoed on every lifecycle frame. Gated on substring so the 91% of frames that are `*.delta` cost one scan; an unparseable `codex.rate_limits` **fails closed** (dropped), since it is advisory and an unknown shape may carry the very fields being removed. Not yet covered: `Retry-After` synthesis reads `Anthropic-Ratelimit-Unified-*` only, and no Codex 429 has been captured to derive from.
- `ratelimit` — keyed `RPM` + `Concurrency` (pure counters; policy/limit lives in the caller).
- `clienttoken` — runtime store of client access tokens.
- `clientguard` — shared ingress UA blocklist.

### Other transports & helpers

- `codexws` — Codex-over-WebSocket upstream transport. This is how real Codex talks: the 0.147.0 Desktop capture contains **no** HTTP `/responses` call at all. `BuildUpstreamHeaders` keeps its positional signature (both forks call it that way) and delegates to `BuildUpstreamHeadersWithOptions`, which takes the stable session id and installation id; its `model`/`serviceTier` arguments are now accepted and ignored, since the routing hint they fed does not belong on a handshake. Header names are written as raw lowercase map keys and `handshakeOrderConn` reorders the emitted block, because Go would otherwise sort them alphabetically — an order no genuine client produces, and fingerprinting the TLS layer while emitting an alphabetised header block leaves the two halves disagreeing. One known delta remains: `EnableCompression` makes gorilla advertise `permessage-deflate; server_no_context_takeover; client_no_context_takeover` where real Codex sends `permessage-deflate; client_max_window_bits` — **do not "fix" the string**, gorilla implements only the no-context-takeover mode and a server not asked to disable context takeover may keep compressor state its inflater cannot decode.
- `thinkingsig` — mid-conversation credential-switch detection + `thinking`-signature sanitization/recovery.
- `advisor` — parses `message_delta.usage.iterations[]` (advisor sub-call billing).
- `stream` — framework-agnostic SSE relay (keepalive + lazy commit + terminal detection); the forks' streamers wrap it.
- `backup` — off-host encrypted (NaCl) snapshot of an app's critical SQLite/state.

## Conventions worth knowing

- **All identity derivation is content-addressed** — no random UUIDs except `X-Client-Request-Id` and the internal `event_id`. New stable identifiers derive from `accountKey` (or `accountKey + clientToken` when they should differ per downstream user), so they survive credential-file rotation.
- **OAuth credential-file fields are append-only** — `parseFile` (`auth/oauth.go`) tolerates missing fields via the `_ = raw["new_field"].(...)` pattern so old files keep loading.
- **Pricing & health thresholds are behavioural constants** — changing `hardFailureThreshold`, `degradedProbeAfter`, the pricing weights, or a `transientErrFragments` entry changes production behaviour in both forks at once. Pair every such change with a test.
- **Fingerprint constants must match `crack/`** — never hand-edit a User-Agent/beta/body-shape without a capture backing it; the diff belongs in `crack/claudev<ver>/SPEC.md`.
- **Probes and local preparation errors are not credential failures** — portal probes (`codex_usage`/`codex_subscription`/`codex_reset`) and `PrepareClaudeCodeRequest` failures must never call `MarkFailure` or trigger failover.
